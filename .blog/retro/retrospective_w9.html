CH 01한국어를 어떻게 쪼개나 — 형태소 분석기 선택#

학습

영어는 공백으로 단어가 갈리지만 한국어는 "용의자와", "변호사가"처럼 조사가 붙어 공백만으로는 못 나눈다. 그래서 형태소 분석이 첫 단추다. 0622엔 KoNLPy의 여러 분석기(Okt·Kkma·Komoran·Hannanum)를 같은 문장에 돌려 비교했다.

의문 → 비교 분석기마다 결과가 다른데, 무엇을 기준으로 골라야 하나?
분석기특징체감
Okt가볍고 빠름, 구어/신조어에 무난속도·간편 — 기본값으로 자주 채택
Kkma(꼬꼬마)세종 말뭉치 기반, 세밀한 품사 태깅정확하지만 느림
Komoran오탈자·띄어쓰기에 견고실문서에 안정적
HannanumKAIST 기반, 오래된 표준환경 의존 큼
기준 확정 "정답 분석기"는 없고 속도(Okt) ↔ 정밀도(Kkma)의 트레이드오프가 있었다. 실습 규모가 작을 땐 Okt로 빠르게, 품사 단위 정밀도가 필요하면 Kkma를 쓰는 식으로 목적에 맞춰 고르는 게 맞았다.

의문 → 반전 — 한 글자는 다 지워도 될까

의문 불용어·한 글자 토큰을 지우다 멈칫했다 — "한 글자도 중요할 수 있지 않나?"
깨달음 맞는 걱정이었다. 한국어엔 집·차·병·일·삶처럼 의미 있는 한 글자 명사가 수천 개라, "쓸 단어"를 화이트리스트로 모으는 건 비현실적이고 오히려 "버릴 한 글자"만 블랙리스트로 관리하는 게 맞았다. 더 나아가 BERT·GPT 시대엔 조사·한 글자·문장부호까지 문맥째로 넣는, 전처리 최소화가 기본이라는 것도 이때 알았다 — 다만 이번 주의 Word2Vec/통계 기반에선 여전히 정제가 필요했다.

의문 → 시행 — 워드클라우드가 메모리에서 죽었다

GPT-3 논문 한국어 번역문에서 명사를 뽑아 빈도 워드클라우드를 그리려다, 그림을 만드는 단계에서 멈췄다.

예상 밖 텍스트 처리는 다 끝났는데 정작 그림(픽셀 배열) 단계에서 막혔다. 워드클라우드가 600×800 캔버스의 점유 맵을 uint32로 잡으면서 메모리를 요구한 것.

다음으로 — 토큰으로 쪼갰으니, 이제 그 토큰들을 컴퓨터가 셈할 수 있는 숫자(벡터)로 바꿀 차례다.

CH 02단어를 숫자로 — BOW에서 TF-IDF까지#

학습 — 시행

0623엔 가장 기본적인 벡터화를 직접 구현했다. 문장을 토큰화해 단어→인덱스 사전을 만들고, 등장 횟수를 세어 BOW(Bag of Words) 벡터를 만든 뒤, 문서×단어 행렬(DTM)과 TF-IDF로 확장했다. sklearn CountVectorizer와도 비교했다.

의문 → 관찰 단순히 횟수만 세면, 모든 문서에 흔한 단어(조사·"이다" 등)가 가장 중요한 단어처럼 보이지 않을까?
표현무엇을 담나한계
BOW / DTM단어별 등장 횟수흔한 단어가 과대평가, 순서 정보 소실
TF-IDF흔할수록 가중치↓ (희소·변별 단어 강조)여전히 의미·문맥은 못 담음
배운 점 TF-IDF는 "그 문서에서만 자주 나오는 단어"에 높은 가중치를 줘 BOW의 흔한-단어 문제를 완화했다. 하지만 셋 다 단어를 서로 독립된 칸으로만 본다 — "왕−남자+여자=여왕" 같은 의미 연산은 불가능했다. 이 한계가 다음 단계(분산 표현, Word2Vec)로 가는 이유였다. 직접 구현과 CountVectorizer를 나란히 보니, 라이브러리가 vocabulary 관리를 자동화할 뿐 원리는 같다는 것도 확인했다.
다음으로 — 횟수 기반 표현의 천장을 봤으니, 본격적인 전처리 차이를 정리하고 의미를 학습하는 임베딩으로 넘어간다.

의문 → 관찰 — 같은 문장, 분석기별로 얼마나 다른가

"살인 용의자와 변호사가 주고받는 대화…"라는 한 문장을 Kkma와 Mecab에 같이 돌려 봤다.

3_형태소_분석_실습1.ipynb — 같은 문장, 분석기별 결과
[꼬꼬마(Kkma)] 품사까지 세밀하게:

배운 점 Kkma는 NNG(일반명사)·JKS(주격조사)까지 품사를 달아 주는 대신 무거웠고, Mecab은 토큰만 빠르게 끊어 줬다. CH01의 트레이드오프가 실제 출력으로 확인된 셈이다 — "무엇을 분석에 쓸 것인가(품사? 토큰만?)"가 분석기 선택을 결정했다.
다음으로 — 토큰을 잘 뽑았으니, 드디어 그 토큰에 '의미'를 학습시키는 분산 표현(Word2Vec)으로 간다.

CH 04의미를 학습하다 — Word2Vec과 FastText#

학습

0625의 핵심. 뉴스 문장 묶음(Okt 명사 추출)으로 Word2Vec을 직접 학습했다 (vector_size=100, window=3, epochs=100, 단어 사전 77개). "비슷한 문맥에 나오는 단어는 비슷한 벡터가 된다"는 가설을 점수로 확인했다.

의문 → 실험 횟수 기반(TF-IDF)으로는 못 했던 "의미 유사도"가, 학습한 임베딩에서는 정말 숫자로 나올까? '대회'와 가까운 단어를 물어봤다.
word2vec_모델_실습하기.ipynb — model.wv.most_similar('대회')
[('데이터', 0.8950), ('선수', 0.8785), ('추천', 0.8765),
 ('모델', 0.8750), ('올림픽', 0.8741), ('러닝', 0.8729),
 ('분석', 0.8706), ('단어', 0.8704), ('사이', 0.8677), ('결과', 0.8671)]

similarity('대회', '올림픽') = 0.87414414

코드로 본 임베딩 학습 — Skip-gram으로 문맥을 학습

중심 단어로 주변 단어를 맞히는 Skip-gram(sg=1) 방식으로, 100차원·window 3으로 직접 학습했다.

from gensim.models import Word2Vec

model = Word2Vec(
    sentences=sentences,   # Okt 명사 토큰화한 문장 리스트
    sg=1,                  # Skip-gram (중심→주변 예측)
    vector_size=100,       # 단어당 100차원 벡터
    window=3,              # 좌우 3단어를 문맥으로
    min_count=1, workers=2, epochs=100, seed=42,
)
print(model.wv.most_similar('대회', topn=10))   # [('데이터',0.8950), ..., ('올림픽',0.8741), ...]
print(model.wv.similarity('대회', '올림픽'))     # 0.87414414
관찰 77단어짜리 작은 코퍼스라 '데이터·모델·러닝'처럼 뉴스 주제어가 같이 섞여 들어왔다. 그래도 '대회'↔'올림픽'(0.874), '아이폰'↔'갤럭시'처럼 의미적으로 맞는 짝이 분명히 상위에 올라왔다 — 횟수 표현(CH02)에선 불가능했던 결과다.

의문 → 비교 — 같은 데이터, FastText는 왜 더 가깝게 보나

같은 데이터를 FastText로 다시 학습해 '대회'–'올림픽'을 비교했다.

배운 점 FastText가 0.9527로 더 높았다. Word2Vec은 단어를 통째로 하나의 벡터로 보지만, FastText는 단어를 글자 n-gram(서브워드)으로 쪼개 학습해 형태가 닮은 단어·희귀어·오타에 강하다. 작은 코퍼스에서도 일반화가 잘 되는 이유였다 — "단어를 어떤 단위로 보느냐"가 임베딩 품질을 갈랐다. (CH01의 형태소 단위 고민이 임베딩까지 이어진 셈이다.) 학습한 모델은 .model로 저장·재로드해 vocab 77개가 그대로 복원되는 것도 확인했다.

의문 → 해부 — 왜 '배'는 문맥이 달라도 같은 벡터인가

임베딩이 신기해서 한 발 더 들어갔다. "타는 배 / 먹는 배 / 신체 배"가 다 같은 벡터로 나온다는 걸 알고 의문이 생겼다.

의문 → 내부 구조 "주변 문맥에 따라 뜻이 바뀌는데, 왜 Word2Vec은 '배'를 항상 같은 숫자 배열로 줄까? 내부가 어떻게 생겼기에?"
깨달음 — 정적 임베딩의 한계 Word2Vec은 학습이 끝나면 단어→벡터 고정 룩업 테이블이 된다. 여러 의미의 '배'가 학습 중 한 칸에서 충돌하며 중간값(평균)으로 수렴하기 때문에 동음이의어를 구분하지 못한다. 이걸 푸는 게 동적 임베딩(BERT·GPT) — 문장 전체를 보고 매번 다른 벡터를 만든다. "임베딩을 뽑는다"가 요즘은 사전학습 트랜스포머의 문맥 벡터를 뜻한다는 것까지 이때 연결됐다.

의문 → 원리 — Skip-gram은 왜 빠르고, 벡터 덧셈은 왜 되나

의문 ① "조밀 행렬 곱셈을 왜 회피해서 효율이 오르지?" — 5만 차원 one-hot 중 1만 1이고 나머지가 0인 벡터를 통째로 곱하는 건 낭비다. 그래서 룩업(인덱싱)으로 그 행만 바로 꺼내 비용을 O(V)→O(K)로 줄이고, 출력엔 네거티브 샘플링으로 일부만 갱신한다. 흔한 단어를 확률적으로 빼는 서브샘플링까지 더해 2~10배가 빨라졌다.
깨달음 ② — 의미가 좌표가 되는 이유 "러시아 + 강 ≈ 볼가강" 같은 덧셈이 되는 건, 각 차원이 의미 속성(국가성·액체성·흐름성…)처럼 작동하기 때문이다. 벡터는 단어의 "의미 성분 함량표"이고, 학습이 내적을 최적화하며 공간을 정렬해 덧셈이 선형으로 통한다. Skip-gram은 문장을 만드는 모델이 아니라 의미의 지도를 그리는 모델이었다.
다음으로 — 단어를 의미 벡터로 바꿨으니, 이제 그 벡터의 '순서'까지 읽어 문장 전체의 감정을 분류하는 LSTM으로 간다.

CH 05언어 모델 — LSTM 감성분류와 호환성의 벽#

학습

0626엔 IMDB 영화평 감성분류를 PyTorch Lightning LSTM으로 구성했다 (Embedding(128) → LSTM(hidden 128, 1층, dropout 0.3) → Linear(128, 2), max_len 200·batch 64·lr 1e-3). 그런데 모델보다 "돌아가게 만드는 일"에서 막혔다.

의문 → 정리 — 왜 LSTM이고, 그 다음은 무엇인가

의문 "RNN/LSTM에서 tanh·가중치가 계속 곱해지며 앞쪽 정보가 사라지는 것, 이걸 뭐라고 부르지?"
깨달음 — 장기 의존성 문제 두 얼굴이 있었다 — 순방향으로는 정보 소실(문장 뒤로 갈수록 앞 단어가 희석), 역방향으로는 기울기 소실(학습 신호가 사라짐). LSTM은 Cell State라는 고속도로로 이를 일부 완화한다. 그래도 한 벡터로 압축하는 Seq2Seq의 고정 벡터 병목은 남아, 디코더가 매번 원문 전체를 다시 보는 어텐션(모든 위치에 가중치를 주는 미분 가능한 'soft' 탐색)으로 이어진다 — IMDB pooling(8주차)에서 "마지막 한 시점 대신 전 구간"을 골랐던 직관과 같은 흐름이었다.

의문 → 시행 — 클래스 수가 안 맞는다

모델이 학습 직전 손실 계산에서 어긋났다. 출력층을 output_size=3으로 둔 게 원인이었다 — IMDB는 긍정/부정 2진 분류인데.

배운 점 output_size=3 → 2로 고치고, 정확도 지표도 BinaryAccuracy(task="binary")로 태스크 타입을 일치시켜 해결했다. 딥러닝 디버깅의 절반은 모델 수식이 아니라 차원·태스크 타입·라이브러리 호환성을 맞추는 일이라는 걸, "긍정/부정" 예측이 마침내 나오기까지의 과정에서 배웠다. (8주차 0618에서 잡은 "분류는 클래스 수부터 맞춘다"가 그대로 재발한 셈이다.)

CH 06종합 회고 — 자연어 첫 주의 교훈#

잘한 점 / 부족했던 점 / 다음 한 수

  • 잘한 점 — BOW→TF-IDF→Word2Vec→FastText로 표현의 사다리를 직접 올라가며, 각 단계의 한계를 다음 단계가 어떻게 메우는지 유사도 점수로 확인했다.
  • 부족했던 점 — Word2Vec 코퍼스가 77단어로 너무 작아 주제어 오염이 컸다. LSTM은 "돌아가게" 만드는 데 시간을 다 써, 최종 test 정확도까지 정량 비교하진 못했다.
  • 다음 한 수 — 더 큰 한국어 코퍼스로 Word2Vec/FastText를 재학습해 유사도 안정성을 보고, 학습한 임베딩을 LSTM 입력으로 연결해 감성분류 정확도를 끝까지 측정한다. 그리고 이번 주 곁가지로 읽은 트랜스포머 논문을 다음 주 실습으로 잇는다.
곁가지로 파고든 이론 — 어텐션에서 트랜스포머로 실습과 별개로 논문(신경망 기계번역·Attention Is All You Need)을 읽으며 의문을 이어 갔다. "RNN을 아예 버린다(dispensing with recurrence)는 게 정말 가능한가?" — 가능했다. RNN은 순서대로만 읽어 병렬화가 안 되고 장기 의존성에 약한데, 트랜스포머는 모든 단어를 동시에 서로 비교(self-attention)해 병렬 학습 + 장거리 직접 연결을 얻는다. "위치는 1·2·3 정수로 주면 될 텐데 왜 sin/cos?"라는 의문도 풀렸다 — 주기함수라야 상대 거리가 선형으로 표현되고 학습보다 긴 문장으로도 외삽이 된다. (이건 다음 주 정식 커리큘럼이라 회고 본문이 아닌 예고로 남긴다.)
관통 교훈 다섯 가지
  1. 한국어는 쪼개기부터다. 공백이 아니라 형태소가 토큰의 단위이고, 분석기 선택은 속도(Okt)↔정밀도(Kkma)의 트레이드오프다.
  2. 횟수는 의미를 못 담는다. BOW·TF-IDF는 변별엔 좋아도 "올림픽≈대회" 같은 의미 관계는 분산 표현(Word2Vec)에서 비로소 숫자가 됐다.
  3. 단어를 보는 단위가 품질을 가른다. 서브워드를 쓰는 FastText가 같은 데이터에서 0.874→0.953으로 더 의미를 잘 잡았다.
  4. 정적 임베딩엔 천장이 있다. Word2Vec은 '배'를 평균 하나로 뭉갠다 — 동음이의어를 풀려면 문맥마다 다른 동적 임베딩(BERT·GPT)이 필요하다.
  5. 모델보다 환경이 먼저 막는다. torchtext 호환성·출력 차원 같은 현실 장벽을 넘는 게 딥러닝 실습의 절반이었다.
