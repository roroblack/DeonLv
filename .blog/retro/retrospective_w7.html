CH 01첫 신경망(heart DNN) — tanh에서 ReLU로, 그리고 데이터 셔플#

학습

심장병 분류(heart) 데이터를 PyTorch DNN으로 세웠다. 층을 쌓고 활성화함수를 고르고 손실·최적화를 정하는, '모델을 직접 조립하는' 첫 경험이었다.

의문 → 시행 ① 은닉층을 키웠더니 더 나빠졌다

성능을 올리려고 tanh를 쓰는 은닉층(뉴런 5000개)을 오른쪽에 추가했더니, 결과가 이전보다 나빠졌다. tanh가 출력을 −1~1로 뭉개면서 손실값이 더 줄지 않고 정체했다.

가설 tanh가 값을 좁은 범위로 압축해 신호가 죽는다면, 양수를 그대로 통과시키는 ReLU로 바꾸면 x 값이 살아 학습이 풀릴 것이다.
결론(중간) ReLU로 바꾸자 정체가 풀렸다. 활성화함수 하나가 학습의 성패를 가른다는 걸 첫날 체감했다.

의문 → 시행 ② 정확도 100%인데 왜 이상한가

데이터 중 처음 100개만 잘라 학습했더니 혼동행렬이 한 칸에 몰리고 검거율(recall)이 1.0으로 나왔다. 알고 보니 환자(1) 데이터가 앞쪽에 모여 있어, 그 구간만 떼어 학습한 탓이었다.

heart_pytorch_dnn.ipynb — 처음 100개 슬라이싱 · PyTorch · 학생 실제 실행
[ raw[:100] — 처음 100개만 사용 ]
혼동행렬:
[[30]]
recall(검거율) = 1.0   ← 환자(1)만 앞쪽에 몰린 구간을 학습

[ 해결: raw[:100] 대신 무작위 셔플 슬라이싱 ]
raw = raw.sample(frac=1)        # 행을 랜덤하게 섞은 뒤 자른다
→ 정상인과 환자가 섞여, 100% 미만의 정상적인 분포로 평가됨
함정 순서가 정렬된 데이터를 앞에서부터 자르면 한 클래스만 학습된다. 자르기 전 셔플이 먼저다.

의문 → 관찰 ③ 시드를 빼면 손실값만 흔들린다

난수 시드(SEED)를 제거하자 최종 정확도·F1(0.802 / 0.820)은 그대로인데 손실값만 매 시행 달라졌다. 예측을 (확률 > 0.5)로 자르는 분류 특성상, 임계값을 넘기만 하면 라벨은 같고 손실의 소수점만 흔들리기 때문이었다.

배운 점 망가졌던 결과(정확도 0.648)를 활성화함수·셔플·튜닝으로 F1 0.75까지 끌어올렸다. 활성화함수 선택과 데이터 분할(셔플)이 학습 자체를 좌우한다.
다음으로 — ReLU가 tanh보다 나았다. 그런데 ReLU·Sigmoid·tanh는 왜 학습 속도가 이렇게 다를까.

CH 02활성화함수와 기울기 소실 — ReLU는 왜 더 빨리 수렴하나#

학습 — 네 가지 활성화함수

활성화함수는 뉴런의 출력을 비선형으로 바꿔, 신경망이 직선이 아닌 경계를 그릴 수 있게 한다. 대표적인 넷(Sigmoid·Tanh·ReLU·LeakyReLU)을 그려 보면 출력 범위와 모양이 제각각이다 — Sigmoid는 (0,1), Tanh는 (−1,1)로 압축하고, ReLU는 음수를 0으로 자른다.

의문 → 시행 — 어느 함수가 더 빨리 수렴하나

나선형 다중분류(spiral)에서 같은 망을 ReLU와 Sigmoid로 각각 학습시켜 비교했다.

Epoch [ 2000/10000] | Loss: 0.052234 | Accuracy: 0.9933

   학습 시간 8초 vs 15초 · 최종 loss 0.011489 vs 0.011644

의문 → 해결 — Sigmoid에서 기울기 소실은 왜 생기나

Sigmoid가 더딘 이유를 개념 수치로 직접 확인했다. Sigmoid의 미분은 σ(x)(1−σ(x))로, 최대가 0.25(x=0)이고 입력 절댓값이 커지면 0으로 압축된다.

dl_w7_runner.py §01 · 시그모이드/ReLU 미분 · Python 3.13.5 · PowerShell
x        : [-6. -2.  0.  2.  6.]
σ(x)     : [0.0025 0.1192 0.5    0.8808 0.9975]
σ'(x)    : [0.0025 0.105  0.25   0.105  0.0025]  ← 최대는 x=0에서
σ'(0) 최대 기울기 = 0.2500
ReLU'(x) : [0. 0. 0. 1. 1.]  ← x>0이면 1, 소실 없음

역전파는 층마다 이 국소 기울기를 곱해 내려간다. 0.25를 깊이만큼 곱하면 급격히 0으로 사라진다 — 이것이 기울기 소실이다.

dl_w7_runner.py §02 · 0.25의 층별 누적 · Python 3.13.5 · PowerShell
시그모이드 1층: 0.25^1 = 0.25000000
시그모이드 2층: 0.25^2 = 0.06250000
시그모이드 4층: 0.25^4 = 0.00390625
시그모이드 8층: 0.25^8 = 0.00001526
  (학생 노트의 0.25×0.25×0.25×0.25 = 0.003906 와 일치)
ReLU 4층     : 1.0^4 = 1.0  ← 신호가 살아서 전달
기계적 증거 Sigmoid 망을 10000 epoch 학습한 뒤 가중치를 꺼내 보니, 한 층(2.weight)의 값이 초기 난수 스케일 그대로였다. 역전파가 닿지 못해 가중치가 갱신되지 않은 것 — 기울기 소실의 직접 증거다. (ReLU·tanh 층의 가중치는 학습 중 크게 변해 있었다.)
배운 점 활성화함수의 미분 특성이 학습 속도와 수렴을 정한다. Sigmoid는 0.25 상한 때문에 깊은 망에서 신호가 사라지고, ReLU는 양수 기울기가 1이라 신호를 살려 더 빨리 수렴한다.
다음으로 — 활성화함수로 신호를 살렸다면, 그 신호로 '얼마나 세게 고칠지'를 정하는 건 손실함수다.

CH 03손실함수 — CrossEntropy와 MSE는 무엇이 다른가#

의문 → 시행 — 다중분류에 MSE를 쓰면

Fashion-MNIST CNN의 손실함수를 CrossEntropyLoss에서 MSELoss로 바꿔 봤다. 바로 크기 불일치 에러가 났다 — 예측은 [300, 10]인데 정답은 [300]이라 빼기가 안 됐다.

# 정답을 원-핫으로 만들고, 정확도·평가·혼동행렬 코드를 argmax로 맞춘다
# correct += (predicted == labels).sum().item()
correct += (predicted == labels.argmax(dim=1)).sum().item()
all_labels.extend(labels.argmax(dim=1).cpu().numpy())

의문 → 관찰 — 두 손실의 '수정 강도'가 다르다

왜 결과가 달라지는지 초기 한 스텝의 역전파 기울기를 numpy로 직접 계산했다. 로짓 [0.5, 0.4, 0.1], 정답 0번일 때:

dl_w7_runner.py §03 · CrossEntropy vs MSE 기울기 · Python 3.13.5 · PowerShell
로짓 z         : [0.5 0.4 0.1]
softmax 확률 p : [0.39 0.35 0.26] (합=1.00)
CE  기울기 p−y : [-0.61  0.35  0.26]
MSE 기울기 2(z−y): [-1.   0.8  0.2]
→ 오답 1·2번 칸 수정 강도: CE [0.35 0.26] vs MSE [0.8 0.2] (MSE가 더 강함)

CrossEntropy는 정답 확률이 오답보다 높기만 하면 수정을 거의 멈추지만, MSE는 오답 칸에 값이 남아 있으면 강하게 눌러 그 활성화 자체를 지운다. 실제 분류에서도 그 차이가 드러났다.

fashion_pytorch_cnn.ipynb — 손실함수별 결과 · PyTorch · 학생 실제 실행
[ MSELoss ]      F1: 0.911   드레스→풀오버 오인 31 → 8,  코트→풀오버 87 → 39 (절반↓)
[ CrossEntropy(원-핫) ]  F1: 0.896   ← 오히려 미세 하락
배운 점 MSE는 뜬금없는 오답 칸의 활성화를 강하게 제거해, 비슷한 옷을 헷갈리는 횟수를 절반으로 줄였다. 다만 CrossEntropy를 원-핫으로 바꾸면 옷의 하위분류(상의류 유사성) 개념을 못 살려 오히려 미세하게 떨어졌다. 손실함수는 '무엇을 얼마나 세게 고치는가'를 정한다 — 문제와 표현에 맞게 골라야 한다.
다음으로 — 손실·활성화를 정했다면, 이미지에는 그에 맞는 구조(CNN)가 있다.

CH 04CNN 학습 — 에폭과 최적화는 한 묶음#

학습

Fashion-MNIST를 CNN으로 학습했다(CIFAR-10도 같은 합성곱 흐름으로 다뤘다). 합성곱으로 이미지의 공간 구조를 활용하는 구조다. 앞 챕터의 손실함수 실험까지는 10 에폭 기준이었다 — 여기서 두 가지를 더 밀어붙였다.

의문 → 시행 ① 에폭을 10에서 20으로

더 오래 학습하면 좋아질까? 같은 CNN을 20 에폭으로 늘려 돌렸다.

fashion_pytorch_cnn.ipynb — M_EPOCH 20 (CrossEntropy) · PyTorch · 학생 실제 실행
CNN 학습 시작
Epoch [01/20] Loss: 0.6698 Accuracy: 76.61%
Epoch [10/20] Loss: 0.2232 Accuracy: 91.80%
Epoch [15/20] Loss: 0.1802 Accuracy: 93.44%
Epoch [20/20] Loss: 0.1442 Accuracy: 94.79%
총 학습 시간: 1391.6초

최종 테스트 정확도: 91.08%   F1 점수: 0.911
( 10 에포크 기준 F1 0.896 → 20 에포크 F1 0.911 로 향상 )

학습 정확도가 91.80%(10ep)에서 94.79%(20ep)로, 테스트 F1도 0.896 → 0.911로 올랐다. 혼동행렬도 대각선(정답)이 더 또렷해졌다 — 더 학습할 시간을 주니 전반적인 수치가 함께 좋아졌다.

의문 → 시행 ② 최적화 함수를 Adam에서 SGD로

최적화 함수만 Adam → SGD(경사하강법)로 바꿔, 같은 3 에폭을 돌렸다. 결과는 처참했다.

fashion_pytorch_cnn.ipynb — 최적화 Adam→SGD · PyTorch · 학생 실제 실행
[ SGD · 3 에폭 ]
Epoch [01/3] Loss: 2.3001 Accuracy: 14.54%
Epoch [03/3] Loss: 2.2776 Accuracy: 22.93%
최종 정확도: 22.33%   F1 점수: 0.223   ← 같은 3 에폭인데 Adam 대비 처참

[ SGD · 에폭을 10으로 늘리면 ]
Epoch [06/10] Loss: 2.2329 Accuracy: 25.50%
Epoch [10/10] Loss: 2.0872 Accuracy: 46.48%   ← 회복 중(여전히 낮음)

Adam은 가중치별 기울기 크기에 따라 보폭(lr 비율)을 조절한다 — 기울기가 작은 가중치에는 보폭을 키우고, weight decay로 과한 값을 누르며 효율적으로 수렴한다. 반면 SGD는 일정한 lr만 가하므로 같은 3 에폭으로는 한참 모자랐고(22.33%), 에폭을 10으로 늘리자 46.48%까지 회복했다 — 그래도 Adam의 단 몇 에폭에는 못 미친다.

배운 점 최적화 함수와 에폭은 한 묶음이다. Adam은 가중치마다 보폭(lr)을 적응적으로 조절해 적은 에폭으로도 빨리 수렴하지만, SGD처럼 lr이 고정이면 같은 성능을 내는 데 훨씬 많은 에폭이 필요하다. 그리고 더 학습(에폭↑)은 대체로 성능을 올린다(F1 0.896→0.911).
그래서 — 첫 주를 돌아보면, 매 실습이 '선택(활성화·손실·최적화·에폭)이 결과를 가른다'는 같은 이야기였다.

CH 05종합 회고 — 딥러닝 첫 주의 교훈#

잘한 점 / 부족했던 점 / 다음 한 수

  • 잘한 점 — 의문을 말로 끝내지 않고 코드·수치로 확인했다. 가중치 덤프로 죽은 노드를, 혼동행렬로 데이터 쏠림을, numpy 손계산으로 0.25·기울기 강도를 직접 봤다.
  • 부족했던 점 — PyTorch 망 구조 설계와 학습률 스케줄을 감으로 만진 부분이 있었다. 다음엔 더 체계적으로.
  • 다음 한 수 — 오차역전파(Day6)·다중 퍼셉트론과 최적화함수(Day7)·오버피팅 방지(Day8)를 마치고, 이어 교과목3 LLM(자연어)으로 넘어간다.
관통 교훈 네 가지 ① 활성화함수가 학습 속도·기울기를 정한다 — Sigmoid의 0.25 상한이 깊은 망에서 신호를 지운다.
② 손실함수가 수정 강도를 정한다 — MSE는 오답 활성화를 강하게 누르고, CrossEntropy는 순위만 맞으면 멈춘다.
③ 데이터 분할·전처리가 여전히 절반 — 셔플 없이 자른 데이터가 정확도 100%의 착시를 만들었다.
