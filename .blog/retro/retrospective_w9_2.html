CH 01출발 — 팀 배정과 베이스라인(Bank Churn)#

학습

18일 팀이 배정되고 19일부터 본격 작업을 시작했다. 필수 산출물은 셋 — 데이터 전처리 결과서, 학습 결과서, 학습된 모델이었다. 먼저 작은 정형 데이터(Bank Churn, 학습 8,000 / 테스트 2,000, 이탈 20.4%)로 베이스라인을 세웠다. ML 세 종류(로지스틱·랜덤포레스트·그래디언트부스팅)와 DL(MLP)을 같은 데이터로 비교했다.

의문 → 기준

의문 이탈이 20.4%로 불균형인데 "정확도"만 보면 다 유지(0)로 찍어도 80%가 나온다. 그러면 무엇을 기준으로 모델을 고를까?

비즈니스 목표는 "이탈할 고객을 미리 찾아 잡는다"이므로 Recall(놓치지 않기)을 중시하되, 임계값에 흔들리지 않는 ROC-AUC를 모델 선정 1차 기준으로 삼았다.

train_ml.py · train_dl.py · compare.py — Bank Churn 테스트(2,000건) 성능
모델                Accuracy  Precision  Recall   F1     ROC-AUC
GradientBoosting    0.869     0.782      0.494    0.605  0.870  ⭐
MLP(딥러닝)         0.783     0.480      0.764    0.590  0.862
RandomForest        0.863     0.788      0.447    0.571  0.855
LogisticRegression  0.714     0.387      0.700    0.499  0.777
관찰 → 정리 종합 분별력(AUC)은 GBM이 가장 높았지만, MLP는 Recall이 0.764로 가장 높아 "이탈 후보를 폭넓게 건진다"는 다른 강점을 보였다. "최고 모델"은 하나가 아니라 무엇을 중시하느냐(Recall vs 정밀도)에 달렸다는 걸 첫 표에서 확인했다.
다음으로 — 모델을 바꾸기 전에, 전처리를 더 정교하게 하면 점수가 오를까? 이걸 베이지안 최적화로 정면으로 물어봤다.

CH 02전처리를 더 짜낼 수 있을까 — 베이지안 최적화의 반전#

의문 → 실험

인코딩·스케일링·이상치·불균형 처리(SMOTE 등)와 모델 하이퍼파라미터를 한꺼번에 optuna(TPE) 40회 탐색으로 돌렸다. 5-fold 교차검증 AUC로 평가했다.

가설 전처리 조합을 정교하게 탐색하면 baseline보다 AUC가 의미 있게 오를 것이다.
예상 밖 baseline 0.8662 = best 0.8662. 즉 전처리 탐색으로는 거의 오르지 않았다. 탐색이 꼽은 중요도는 전처리 기법들이 아니라 모델 선택이 0.997로 사실상 전부였고, SMOTE는 오히려 0.8648로 떨어뜨렸다.
배운 점 이 데이터에서 성능을 지배한 건 전처리 레시피가 아니라 모델 종류였다. "전처리를 더 짜내자"는 직관이 항상 통하지는 않는다 — 어디에 병목이 있는지를 먼저 측정해야 노력을 옳은 곳에 쓴다. SMOTE처럼 흔히 권장되는 기법도 데이터에 따라 역효과가 났다.
다음으로 — 작은 정형 데이터에선 GBM이 강했다. 그렇다면 데이터를 수천만 건으로 키우고 "순서"가 있는 행동 로그를 주면, 시퀀스 딥러닝이 GBM을 넘을까? 진짜 데이터로 옮겨갔다.

CH 03데이터를 키우다 — REES46 2,069만 건과 recency의 지배#

학습 → 시행

최종 데이터를 REES46 화장품 이커머스 로그(2019-10~2020-02, 약 2,069만 이벤트)로 바꿨다. 정형 피처(RFM류)와 주별 행동 시퀀스(view·cart·purchase)를 함께 만들고, "계정 이탈"(관찰 기간 뒤 활동 없음)을 라벨로 ML(GBM 등)과 시퀀스 DL(RNN·LSTM·Transformer)을 같은 표본에서 비교했다.

의문 데이터·시퀀스를 키우면 시퀀스 딥러닝이 정형 모델을 넘는가?
retail_rees46 / retail_rees46_multi — 계정 이탈 라벨, 최고 ROC-AUC
단계                  표본/시퀀스          ML 최고          시퀀스 DL 최고      승자
온라인리테일          3,317명 · 월9스텝     GBM 0.745        LSTM 0.742         ML
REES46 1개월          60,000명 · 일21스텝   GBM 0.803        Transformer 0.795  ML(근소)
REES46 5개월(다개월)  80,000명 · 주18스텝   GBM 0.826 ⭐     Transformer 0.818  ML(근소)
CLUE 데이터를 키울수록 전체 AUC는 0.745 → 0.803 → 0.826으로 올랐지만, 세 단계 모두 시퀀스 DL이 GBM을 넘지 못했다. 원인은 모델이 아니라 라벨이었다 — 이 "계정 이탈"은 recency(마지막 활동 후 경과, 중요도 0.094로 압도적)로 거의 환원돼, 순서·패턴이 정답을 거의 안 가른다.
배운 점 recency로 환원되는 문제에선 그 집계 신호를 가장 잘 쓰는 GBM이 작은 데이터에서도, 큰 데이터에서도 1위였다. 시퀀스 DL의 강점(순서 학습)은 발휘될 자리가 없었다. "데이터를 키우면 DL이 이긴다"는 기대 자체가 라벨을 잘못 본 것이었다.
다음으로 — 그렇다면 순서가 실제로 중요한 라벨을 주면 결과가 뒤집힐까? 라벨을 다시 설계했다.

CH 04반전 — 라벨을 다시 세우자 DL이 GBM을 넘었다#

의문 → 재정의

라벨을 네 가지로 나눠 같은 조건에서 비교했다 — base(계정 이탈), A(세션 즉시 이탈: 구매 없이 세션 종료, 입력=구매 직전 이벤트 순서), B(단기 이탈), C(다음 활동까지 시간·회귀). A만 순서가 본질인 과제다.

retail_rees46_labels — 세션 즉시 이탈(라벨 A) ROC-AUC
LSTM (시퀀스 DL)     0.930  ⭐   ← 처음으로 GBM을 넘음
GBM (정형)           0.929
MLP (정형 DL)        0.928
Transformer (시퀀스) 0.927
LogReg (정형)        0.911

참고) recency형 라벨에선 여전히 GBM 우위: base 0.803 · 다개월 0.826
반전 → 결론 모델을 더 키운 게 아니라 문제(라벨)를 순서가 중요한 형태로 다시 세운 것이 승부를 갈랐다. recency로 환원되는 문제엔 GBM이, 순서가 살아 있는 실시간 세션 문제엔 시퀀스 DL이 이긴다 — "라벨의 성격이 어떤 모델이 이길지를 정한다." 이것이 프로젝트 전체를 관통한 한 문장이 됐다.
다음으로 — 순서가 중요한 세션 문제라면, 예측은 "세션이 끝난 뒤"가 아니라 "세션 도중 실시간"이어야 가치가 있다. 그래서 실시간 예측과 서비스로 확장했다.

CH 05실시간과 서비스 — 리플레이 예측과 GAJIMA 앱#

학습 → 시행

운영 사이트가 없어도 실시간을 검증할 수 있었다. 과거 로그를 시간순으로 한 건씩 흘려보내는 리플레이(replay)가 곧 실시간 이벤트 스트림과 같기 때문이다. 세션 이벤트를 1..t까지만 보여주며(미래 누수 차단) 이탈 확률이 갱신되는 과정을 재생하고, "이벤트 몇 개를 보면 충분히 정확한가(정확도@k)"를 측정했다.

배운 점 "실시간 예측"은 거창한 인프라가 아니라 이벤트를 도착 순서대로 처리하는 것이었다. 라이브 사이트 없이 로그 리플레이만으로 실시간 동작과 조기 경보 성능을 정직하게 시연할 수 있었다.

시행 — 데모 앱(GAJIMA)

예측을 실제 서비스 형태로 감쌌다. InsightFace 얼굴 로그인(등록 얼굴과 비교 인증)에 성공한 사용자만 이탈 예측 대시보드를 쓰는 Streamlit 앱이다. 로컬 백엔드(FastAPI)를 cloudflared 터널로 노출하고 Vercel 프런트(gajimasimul)와 연결해, 고객을 조회하면 이탈 확률과 대응 액션(SNS·할인·연관추천)이 뜨도록 만들었다.

정직하게 개입 효과(쿠폰을 보내면 전환↑)는 A/B 실험 없이는 인과적으로 증명할 수 없어, 예측 품질과 타겟팅 시뮬레이션까지만 보이고 "인과 효과는 가정"임을 분명히 했다.
그래서 — 베이스라인부터 대규모·실시간·서비스까지 한 바퀴를 돌며, 처음의 "어떤 모델이 최고인가"는 "문제를 어떻게 세울 것인가"로 바뀌어 있었다.

CH 06종합 회고 — 발표와 배운 점#

잘한 점 / 부족했던 점 / 다음 한 수

  • 잘한 점 — 작은 데이터(Bank)에서 대규모(REES46 2,069만)까지 스케일을 올리며, 라벨 4종(base/A/B/C)을 같은 조건으로 비교해 "라벨이 승자를 정한다"를 수치로 증명했다(세션 A: LSTM 0.930 > GBM 0.929).
  • 부족했던 점 — DL이 이긴 폭이 0.001로 근소했고, 개입 효과는 실험이 없어 가정에 머물렀다. 베이지안 최적화는 이 데이터에선 이득이 거의 없었다(model 중요도 0.997).
  • 다음 한 수 — 세션 라벨에 시간 간격 임베딩·하이브리드(통계+시퀀스)·멀티태스크를 더해 0.930의 천장을 올리고, 조기 경보(정확도@k)를 서비스 지표로 다듬는다.
관통 교훈
  1. 불균형엔 정확도 한 숫자를 믿지 말 것. Recall·F1·AUC로 "어떤 오류를 내는 모델인가"를 본다(이탈은 Recall 중시).
  2. 병목을 먼저 측정. 이 데이터의 성능은 전처리(0.003 미만 기여)가 아니라 모델 선택(0.997)이 지배했다.
  3. 라벨의 성격이 승자를 정한다. recency·집계 → GBM, 순서·세션 → 시퀀스 DL. 모델 교체가 아니라 문제 재정의가 핵심이다.
  4. 실시간은 순서 처리다. 로그 리플레이로 라이브 없이 실시간을 검증·시연할 수 있다.
