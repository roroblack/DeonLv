NAVER 뉴스 카테고리 분류기 (LSTM) 실험

한국어 뉴스를 카테고리로 분류하는 LSTM 모델을 어떻게 만들고, 무엇이 성능을 가르나. 임베딩 → LSTM → 분류로 이어지는 뼈대는 짧지만, 정확도를 실제로 움직인 것은 모델 구조가 아니라 한국어 전처리였다.

CH 01텍스트 분류라는 문제 정의#

학습 → 입력은 문장, 출력은 미리 정의된 라벨

강의 자료는 텍스트 분류를 "문장·문서의 내용을 분석해 미리 정해진 범주(Class) 중 하나 또는 여러 개로 자동 분류하는 작업"으로 정의한다. 입력은 텍스트, 출력은 사전에 정의된 라벨이다. 스팸/정상, 영화 리뷰 긍정/부정이 대표적인 이진 분류이고, IT·교육·건강처럼 세 개 이상 중 하나를 고르면 다중 분류가 된다. 뉴스 카테고리 분류는 후자에 속한다.

분류 과정은 텍스트 수집 → 전처리(정제·토큰화·형태소 분석·불용어 제거) → 벡터화 → 모델 학습 → 예측·평가의 순서로 정리된다. 이 파이프라인에서 딥러닝 모델은 "벡터화된 입력을 받아 예측하는" 한 단계일 뿐이고, 그 앞의 전처리가 한국어에서는 유독 무겁다는 점이 이번 실험의 핵심 주제가 된다.

의문감성 분석(2진)과 뉴스 분류(다중)는 코드 관점에서 얼마나 다른가? 출력 차원만 늘리면 되는가, 아니면 전처리·손실·평가까지 함께 바뀌는가?
다음으로 — 그 답을 확인하려면 먼저 기존 감성 분석 모델의 뼈대를 그대로 읽어봐야 한다.

CH 02임베딩 → LSTM → 분류 뼈대#

시행 → NSMC 감성 분류 LSTM의 설정값 읽기

출발 코드는 네이버 영화 리뷰(NSMC) 데이터로 긍정/부정을 가르는 LSTM 분류기다. 설정값은 하나의 Config 데이터클래스에 모아 두어, 뉴스 분류로 넘어갈 때 어떤 값을 건드려야 하는지 한눈에 보인다.

assignment/LSTM_movie_review.py — 학습 설정(Config)
max_len          = 200        # 문장 최대 길이(패딩 기준)
max_vocab_size   = 20000      # 사전 최대 단어 수
min_freq         = 2          # 2회 미만 등장 단어는 <unk> 처리
batch_size       = 64
embedding_dim    = 128
hidden_dim       = 128
num_layers       = 1
dropout          = 0.3
learning_rate    = 0.001
max_epochs       = 3
val_ratio        = 0.2        # 학습 데이터의 20%를 검증으로 분리

모델 본체는 세 층이다. nn.Embedding이 정수 토큰을 128차원 벡터로 바꾸고, 단방향 nn.LSTM이 시퀀스를 훑고, 마지막 nn.Linear가 클래스 점수를 낸다. 여기서 중요한 세부는 "문장 벡터"를 어떻게 뽑느냐다.

def forward(self, input_ids):
    embedded = self.embedding(input_ids)          # (B, L, E)
    output, (hidden, cell) = self.lstm(embedded)  # hidden: (num_layers, B, H)
    sentence_vector = hidden[-1]                  # 마지막 층의 최종 은닉상태
    sentence_vector = self.dropout(sentence_vector)
    logits = self.classifier(sentence_vector)     # (B, num_classes)
    return logits
배운 점LSTM의 모든 시점 출력을 쓰는 게 아니라 hidden[-1], 즉 마지막 층의 최종 은닉상태 하나를 문장 대표 벡터로 쓴다. 시퀀스 전체를 한 벡터로 요약하는 이 지점이 "가변 길이 텍스트 → 고정 차원 분류"의 다리다.
함정기존 코드 정비 과정에서, LSTM의 모든 시점 출력에 선형층을 걸고 점수를 sum(dim=1)으로 합산하던 비표준 구조와 출력 차원을 3으로 두고 라벨은 2개(0/1)이던 불일치가 문제로 기록됐다. 표준은 마지막 은닉상태 → 선형층, 그리고 출력 차원 = 실제 클래스 수다. 이 원칙은 다음 장에서 뉴스로 확장할 때 그대로 밟게 된다.
다음으로 — 이 뼈대에서 무엇을 바꾸면 2진 감성이 6분류 뉴스가 되는지 짚는다.

CH 03감성 2진에서 뉴스 6분류로#

시행 → 입력 데이터와 출력 차원을 함께 바꾸기

실험 보고서 기준, 뉴스 분류는 IT·스포츠·사회·경제·연예·정치 6개 카테고리를 다룬다. 2진 분류 코드에서 다중 분류로 넘어갈 때 실제로 손대는 지점은 생각보다 좁고 분명하다.

구성 요소감성(2진)뉴스(6분류)
라벨0/1 (부정/긍정)0~5 (IT·스포츠·사회·경제·연예·정치)
분류층 출력Linear(H, 2)Linear(H, 6)
손실 함수CrossEntropyLoss — 그대로 (다중 클래스 지원)
정확도 지표task="binary"task="multiclass", num_classes=6
전처리토큰화 → 정수 인코딩 → 패딩 (동일 파이프라인)

즉 CrossEntropyLoss와 임베딩·LSTM 뼈대는 손대지 않는다. 바뀌는 건 (1) 입력 데이터셋, (2) 마지막 Linear의 출력 차원 2→6, (3) 정확도 메트릭의 task 타입이다. 강의 자료가 다중 분류를 "세 개 이상의 클래스 중 하나를 선택"으로 정의하듯, 소프트맥스 출력이 카테고리 수만큼 늘어날 뿐 문제의 형태는 같다.

의문구조 변경이 이렇게 얕은데 초기 성능은 왜 낮게 나오는가? 다중 클래스라 어려워진 것인가, 아니면 다른 데서 새는 것인가?
다음으로 — 실험의 버전별 정확도 추이를 보면, 성능을 실제로 끌어올린 건 모델이 아니라 데이터·전처리 쪽이었다.

CH 04무엇이 성능을 가르나 — 형태소와 데이터#

관찰 → 버전을 거치며 무엇을 바꿨을 때 올랐나

실험 보고서에는 여러 버전에 걸친 검증·테스트 정확도가 기록돼 있다. 초기 버전들은 검증 정확도가 40~50%대에 머물렀고, 데이터를 늘리고 형태소 분석을 붙인 버전에서 눈에 띄게 올라갔다는 흐름이 핵심이다. 구조를 바꿔서가 아니라 입력 품질을 손봐서 개선됐다는 점이 중요하다.

변경 내용관찰된 방향
초기 다중 분류(공백 토큰화)40~50%대 — 기준선
데이터 약 3배 확대 + 형태소 분석 적용테스트 정확도 뚜렷한 상승
전처리·하이퍼파라미터 정비 누적추가 개선

이유는 강의 자료의 한 문장으로 요약된다. "한국어에서는 조사와 어미가 많기 때문에 형태소 분석이 매우 중요하다." 공백 단위로 자르면 "뉴스가/뉴스를/뉴스는"이 전부 다른 토큰이 되어 사전이 낭비되고 <unk>가 늘어난다. 형태소 분석기(KoNLPy의 Okt·Mecab 등)로 어간과 조사를 분리하면 같은 의미 단어가 하나로 모여 임베딩이 촘촘해진다.

배운 점기존 감성 코드의 토큰화는 정규식으로 특수문자를 제거한 뒤 split()으로 공백 분할하는 방식이었다. 이 단계를 형태소 분석으로 교체하는 것이 한국어 뉴스 분류에서 가장 큰 성능 레버였다. 모델 층을 늘리는 것보다 앞 단이 먼저다.
함정min_freq=2로 희귀어를 <unk> 처리하는 설정은, 공백 토큰화 상태에서는 조사 변형까지 희귀어로 몰아 정보를 더 깎을 수 있다. 형태소 분석으로 토큰이 정규화된 뒤에야 이 임계값이 의도대로 "진짜 드문 단어만" 걸러낸다. 전처리와 사전 설정은 함께 조율해야 한다.
다음으로 — 그러면 이 모델의 성능을 어떻게 읽고, 어디서 한계에 부딪히는지 정리한다.

CH 05평가와 다음 단계(BERT 계열)#

결론 → 지표로 읽고, 문맥의 벽에서 다음 모델로

다중 분류 평가는 정확도 하나로 끝내지 않는다. 강의 자료가 정리한 지표는 Accuracy, Precision, Recall, F1-Score, 그리고 Confusion Matrix다. 6개 카테고리에서는 경제와 사회, IT와 연예처럼 어휘가 겹치는 쌍이 서로 혼동되기 쉬운데, 이 오분류 구조는 혼동 행렬로만 드러난다. 클래스별 데이터 수가 다르면 특정 카테고리로 편향될 수 있다는 점(데이터 불균형)도 자료가 명시한 한계다.

평가 관점 — 다중 분류에서 봐야 할 것
Accuracy       : 전체 정답 비율(불균형이면 과대평가 위험)
Precision/Recall: 카테고리별로 따로 확인
F1-Score       : 두 지표의 조화평균
Confusion Matrix: 어떤 카테고리끼리 헷갈리는지 파악

LSTM은 단어 순서와 문맥을 어느 정도 학습하지만, 같은 단어가 문장마다 다른 의미로 쓰이는 상황(자료의 예: 금융 "은행" vs 나무 "은행")까지는 하나의 임베딩으로 뭉개 버린다. 자료가 최신 기술로 제시하는 BERT 계열(KoBERT·KoELECTRA)은 앞뒤 문맥을 동시에 보는 양방향 학습으로 이 문맥 의존 의미를 구분하고, 적은 데이터로도 파인튜닝만으로 높은 분류 성능을 낸다. 이번 실험의 LSTM은 그 다리를 놓기 위한 기준선인 셈이다.

배운 점한 줄 목표의 답 — 뉴스 LSTM 분류기는 임베딩→LSTM(마지막 은닉상태)→선형층으로 짧게 만들 수 있지만, 성능을 가른 것은 모델 깊이가 아니라 한국어 형태소 전처리와 데이터 양이었다. 그리고 문맥 의존 의미의 벽에서 다음 모델(BERT 계열)로 넘어가는 이유가 생긴다.
