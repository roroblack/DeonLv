CH 01텍스트 분류라는 문제와 6분류 설정#

학습 → 입력은 문장, 출력은 미리 정의된 라벨

강의 자료는 텍스트 분류를 "문장·문서의 내용을 분석해 미리 정해진 범주(Class) 중 하나 또는 여러 개로 자동 분류하는 작업"으로 정의한다. 입력은 텍스트, 출력은 사전에 정의된 라벨이다. 스팸/정상, 영화 리뷰 긍정/부정이 대표적인 이진 분류이고, 세 개 이상 중 하나를 고르면 다중 분류가 된다. 이번 실험의 대상인 IT·스포츠·사회·경제·연예·정치 6개 카테고리 뉴스 분류는 후자다.

분류 과정은 텍스트 수집 → 전처리(정제·토큰화·형태소 분석·불용어 제거) → 벡터화 → 모델 학습 → 예측·평가의 순서로 정리된다. 이 파이프라인에서 딥러닝 모델은 "벡터화된 입력을 받아 예측하는" 한 단계일 뿐이고, 그 앞의 전처리·데이터가 한국어에서 유독 무겁다는 점이 이번 실험의 핵심 주제가 된다.

의문감성 분석(2진)과 뉴스 분류(6분류)는 코드 관점에서 얼마나 다른가? 출력 차원만 늘리면 되는가, 아니면 전처리·손실·평가까지 함께 바뀌는가? 그리고 구조를 그대로 두면 정확도는 무엇으로 움직이는가?
다음으로 — 그 답을 확인하려면 먼저 기존 감성 분석 모델의 뼈대를 그대로 읽어봐야 한다.

CH 02임베딩 → LSTM → 분류 뼈대#

시행 → NSMC 감성 분류 LSTM의 설정값 읽기

출발 코드는 네이버 영화 리뷰(NSMC) 데이터로 긍정/부정을 가르는 LSTM 분류기다. 설정값은 하나의 Config 데이터클래스에 모아 두어, 뉴스 분류로 넘어갈 때 어떤 값을 건드려야 하는지 한눈에 보인다.

assignment/LSTM_movie_review.py — 학습 설정(Config)
max_len          = 200        # 문장 최대 길이(패딩 기준)
max_vocab_size   = 20000      # 사전 최대 단어 수
min_freq         = 2          # 2회 미만 등장 단어는 <unk> 처리
batch_size       = 64
embedding_dim    = 128
hidden_dim       = 128
num_layers       = 1
dropout          = 0.3
learning_rate    = 0.001
max_epochs       = 3
val_ratio        = 0.2        # 학습 데이터의 20%를 검증으로 분리

모델 본체는 세 층이다. nn.Embedding이 정수 토큰을 128차원 벡터로 바꾸고, nn.LSTM이 시퀀스를 훑고, 마지막 nn.Linear가 클래스 점수를 낸다. 여기서 중요한 세부는 "문장 벡터"를 어떻게 뽑느냐다.

def forward(self, input_ids):
    embedded = self.embedding(input_ids)          # (B, L, E)
    output, (hidden, cell) = self.lstm(embedded)  # hidden: (num_layers, B, H)
    sentence_vector = hidden[-1]                  # 마지막 층의 최종 은닉상태
    sentence_vector = self.dropout(sentence_vector)
    logits = self.classifier(sentence_vector)     # (B, num_classes)
    return logits
배운 점LSTM의 모든 시점 출력을 쓰는 게 아니라 hidden[-1], 즉 마지막 층의 최종 은닉상태 하나를 문장 대표 벡터로 쓴다. 뉴스 분류기 TextLSTMClassifier는 여기에 양방향(Bidirectional) 옵션과 Global Max Pooling을 얹을 수 있게 확장됐지만, "가변 길이 텍스트 → 고정 차원 분류"라는 다리는 그대로다.
함정기존 코드 정비 과정에서, LSTM의 모든 시점 출력에 선형층을 걸고 점수를 sum(dim=1)으로 합산하던 비표준 구조와, 출력 차원을 3으로 두고 라벨은 2개(0/1)이던 불일치가 문제로 기록됐다. 표준은 마지막 은닉상태 → 선형층, 그리고 출력 차원 = 실제 클래스 수다. 이 원칙은 다음 장에서 뉴스로 확장할 때 그대로 밟게 된다.
다음으로 — 이 뼈대에서 무엇을 바꾸면 2진 감성이 6분류 뉴스가 되는지, 그리고 그렇게 바꾼 첫 버전들이 왜 기대만큼 안 나왔는지 짚는다.

CH 03Optuna 튜닝과 초기 버전들 — 왜 떨어졌나#

시행 → 출력 차원을 6으로, 데이터를 실제 뉴스로 바꾸기

2진 분류 코드에서 6분류로 넘어갈 때 실제로 손대는 지점은 생각보다 좁고 분명하다. CrossEntropyLoss와 임베딩·LSTM 뼈대는 그대로 두고, (1) 입력 데이터셋, (2) 마지막 Linear의 출력 차원 2→6, (3) 정확도 메트릭의 task 타입만 바꾼다.

구성 요소감성(2진)뉴스(6분류)
라벨0/1 (부정/긍정)0~5 (IT·스포츠·사회·경제·연예·정치)
분류층 출력Linear(H, 2)Linear(H, 6)
손실 함수CrossEntropyLoss — 그대로 (다중 클래스 지원)
정확도 지표task="binary"task="multiclass", num_classes=6
전처리토큰화 → 정수 인코딩 → 패딩 (동일 파이프라인)

여기에 이번 프로젝트는 Optuna 베이지안 탐색을 얹었다. embed_dim·hidden_dim·num_layers·bidirectional·dropout·learning_rate·batch_size 같은 하이퍼파라미터를 사람이 손으로 고르지 않고, MedianPruner로 못한 trial은 조기 중단하며 val_acc가 가장 높은 조합을 자동으로 찾는다. v2부터는 전처리 파라미터(max_vocab·max_len)와 옵티마이저(Adam/AdamW·weight_decay)까지 탐색 공간에 넣었다.

의문구조를 표준으로 맞추고 하이퍼파라미터까지 자동 탐색했는데, 초기 버전 정확도는 왜 오히려 낮게 나오는가? 다중 클래스라 어려워진 것인가, 아니면 다른 데서 새는 것인가?

관찰 → v1이 오히려 제일 높았다는 역설

보고서에 남은 실측치가 흥미롭다. 내장 샘플 150건으로 돌린 v1이 테스트 66.67%로 가장 높았고, 실제 네이버 뉴스를 크롤링해 넣기 시작한 v2·v3에서 오히려 30.77% → 25.0%로 떨어졌다.

v1  SAMPLE_DATA 150건(25/카테고리)   best val 0.7500   test 66.67%
v2  크롤링 일부 + 샘플 130건          best val 0.6000   test 30.77%
v3  크롤링 120건(20/카테고리)         best val 0.4737   test 25.00%  ← 최저

# v3 classification_report (macro avg): P 0.10 / R 0.25 / F1 0.13
# → 스포츠 Recall 1.00, 나머지 카테고리 F1 0.00  (한 클래스로 쏠림)

보고서는 원인을 데이터에서 찾는다. v1의 샘플 데이터는 카테고리 경계가 깔끔했지만, 실제 크롤링 헤드라인은 "연예인 스포츠 기사", "정치·경제 혼재 기사"처럼 경계가 흐리다. 게다가 v3은 120건 ÷ 6카테고리 = 카테고리당 20건, 그중 학습은 약 13건뿐이라 데이터 절대량 자체가 부족했다. 소규모 검증셋(19건)에서는 val_acc가 노이즈에 민감해, lr=0.009864 같은 과대적합 trial이 우연히 val에서 높은 점수를 받아 best로 뽑히기도 했다.

함정v3에서는 모델이 스포츠 하나로만 예측하는 클래스 붕괴(class collapse)가 관측됐다(스포츠 Recall 1.00, 나머지 5개 F1 0.00). 데이터가 너무 적고 lr이 너무 높으면, 다수·쉬운 클래스로 전부 몰아버리는 게 손실을 낮추는 지름길이 되기 때문이다. 정확도 숫자만 보면 25%지만, 실제로는 "분류를 포기한" 상태에 가깝다. v4에서 learning_rate 상한을 5e-3으로 제한하고 데이터를 카테고리당 50건으로 늘린 뒤 이 붕괴는 사라졌다.
다음으로 — v3의 진단이 "데이터 부족"이었다면, 데이터를 실제로 몇 배 늘렸을 때 정확도가 어떻게 움직였는지 실측으로 확인한다.

CH 04데이터를 키우자 올랐다 — v5~v9 실측#

관찰 → 아키텍처는 고정, 데이터만 늘렸을 때의 진행

보고서의 버전 진행을 한 표로 모으면, 정확도를 실제로 끌어올린 레버가 무엇인지가 드러난다. 모델 구조(임베딩→LSTM→선형층)는 처음부터 동일했고, 바뀐 것은 주로 데이터 양과 전처리·조기종료 기준이었다.

배운 점LSTM은 사전학습 지식이 없어 훈련 데이터에서 한국어 의미를 처음부터 배운다. 그래서 클래스당 샘플이 부족하면 임베딩을 제대로 학습하지 못한다. 보고서의 결론 한 줄 — "데이터가 모든 것이다. 동일한 아키텍처로 데이터를 100→500건/카테고리로 늘리는 것만으로 41.67% → 92.83%로 끌어올렸다." 6클래스 한국어 헤드라인 분류에는 클래스당 최소 300~500건이 필요하다는 것이 실증됐다.
다음으로 — 데이터가 큰 레버였다면, 형태소 분석과 조기종료 기준 같은 세부 레버는 실제로 얼마나 기여했는지 뜯어본다.

CH 05형태소·조기종료·클래스 붕괴 뜯어보기#

관찰 → 데이터 다음으로 성능을 움직인 세부 레버들

강의 자료의 한 문장이 형태소의 이유를 요약한다. "한국어에서는 조사와 어미가 많기 때문에 형태소 분석이 매우 중요하다." 공백 단위로 자르면 "뉴스가/뉴스를/뉴스는"이 전부 다른 토큰이 되어 사전이 낭비되고 <unk>가 늘어난다. 이 프로젝트는 KoNLPy의 Okt로 토큰을 만드는데, 명사만 뽑는 방식과 형태소(명사+동사+형용사+부사)를 뽑는 방식을 Optuna가 선택하도록 뒀다.

# 명사만 (v5) — 헤드라인당 평균 3~5토큰, 정보 손실 큼
tokens = okt.nouns("경제부 장관 인플레이션 대책 발표")
# → ['경제부', '장관', '인플레이션', '대책', '발표']

# 형태소 (v6폴더) — 동사/형용사까지 포함해 문맥 보강
tokens = [w for w, pos in okt.pos(text)
          if pos in {'Noun', 'Verb', 'Adjective', 'Adverb'}]
# → ['경제부', '장관', '인플레이션', '대책', '발표', '했다']

보고서 기준 형태소 토큰화 도입은 v5 대비 약 +5~8%p 기여로 기록됐다. 다만 흥미로운 반전이 있다. 데이터가 부족한 v6폴더(1,800건)에서는 Optuna가 use_morphemes=True를 골랐지만, 데이터가 충분한 v9(3,000건)에서는 use_morphemes=False(명사만)를 골랐다. 즉 형태소 분석은 데이터 부족을 보완하는 수단이고, 데이터가 충분하면 명사만으로도 더 빠르고 안정적이라는 것이다.

배운 점또 하나의 세부 레버는 조기종료(Early Stopping) 기준이었다. v6폴더까지는 val_loss가 최소인 시점에 멈췄는데, 이 순간이 val_acc 최고점과 어긋나 정확도 피크를 놓쳤다. LSTM을 val_acc 최대화 기준으로 저장하도록 바꾼 v7폴더에서 +2.23%p가 올랐다. val_loss는 오분류 샘플의 확률 분포에 민감해서, 손실이 최소인 순간과 정확도가 최고인 순간이 다를 수 있다.
함정세부 레버가 항상 좋은 방향으로만 가진 않았다. v8폴더에서 learning_rate를 0.00465 → 0.001로 낮추자 오히려 58.06% → 53.89%로 떨어졌다. ReduceLROnPlateau 스케줄러가 lr을 0.001 → 0.000125로 빠르게 감쇠시켜, 모델이 지역 최솟값에 조기 수렴한 탓이다. "lr은 낮을수록 안전"이라는 직관이 소규모 데이터에서는 역효과를 낼 수 있음을 보여준 회귀 구간이다.

한 가지 유의점. 개별 보고서(tuning_v1~v5)의 버전 번호와, 종합 보고서(tuning_v6)가 쓰는 "폴더" 번호가 완전히 일치하지는 않는다. 그래서 위 수치들은 특정 버전 이름에 못을 박기보다 버전별 진행 방향(데이터↑ → 정확도↑, lr↓ → 회귀)으로 읽는 편이 안전하다. 절대 수치는 각 보고서에 기록된 값 그대로 인용했다.

다음으로 — 그러면 이 모델의 성능을 어떻게 읽고, 어디서 구조적 한계에 부딪혀 다음 모델로 넘어가는지 정리한다.

CH 06평가와 다음 단계(BERT 계열)#

결론 → 지표로 읽고, 문맥의 벽에서 다음 모델로

다중 분류 평가는 정확도 하나로 끝내지 않는다. 강의 자료가 정리한 지표는 Accuracy, Precision, Recall, F1-Score, 그리고 Confusion Matrix다. 실제로 이 프로젝트에서 가장 오래 취약했던 카테고리는 사회였다. "교육부 정책 발표", "법원 판결"처럼 정치·경제와 경계가 모호한 기사가 많기 때문인데, F1이 v5 수준의 0.24에서 v9의 0.82로 올라간 것은 데이터가 5배로 늘어난 뒤에야 이 모호성을 구분하는 패턴이 학습됐기 때문이다.

평가 관점 — 다중 분류에서 봐야 할 것
Accuracy        : 전체 정답 비율(불균형이면 과대평가 위험)
Precision/Recall: 카테고리별로 따로 확인 (사회 F1이 가장 늦게 오름)
F1-Score        : 두 지표의 조화평균
Confusion Matrix: 어떤 카테고리끼리 헷갈리는지 파악
                  (v3에서 스포츠 한 클래스 쏠림 = 클래스 붕괴 탐지)

LSTM은 단어 순서와 문맥을 어느 정도 학습하지만, 같은 단어가 문장마다 다른 의미로 쓰이는 상황(자료의 예: 금융 "은행" vs 나무 "은행")까지는 하나의 임베딩으로 뭉개 버린다. 자료가 최신 기술로 제시하는 BERT 계열(KoBERT·KoELECTRA)은 앞뒤 문맥을 동시에 보는 양방향 학습으로 이 문맥 의존 의미를 구분하고, 적은 데이터로도 파인튜닝만으로 높은 성능을 낸다. 이 프로젝트에서도 KoBERT(klue/bert-base)·KoELECTRA(koelectra-base-v3)를 붙인 탐색이 이어졌는데, 첫 trial부터 val_acc 0.94+를 기록하고 최고 0.9618(KoELECTRA)에 이르렀다. 데이터가 300건/카테고리에 불과해도 LSTM의 500건 수준을 가뿐히 넘겼다.

배운 점한 줄 목표의 답 — 뉴스 LSTM 분류기는 임베딩→LSTM(마지막 은닉상태)→선형층으로 짧게 만들 수 있고, 그 뼈대는 v1부터 v9까지 그대로였다. 성능을 가른 것은 모델 깊이가 아니라 데이터 양(41.67%→92.83%)이었고, 그 다음이 형태소 전처리와 조기종료 기준이었다. 그리고 문맥 의존 의미의 벽에서, 사전학습을 가진 BERT 계열로 넘어가는 이유가 생긴다.
